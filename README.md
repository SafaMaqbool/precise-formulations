# Precise Formulations

Custom store for Precise Formulations: three products, manual Venmo/Zelle payment, order emails, payment reminders and an admin portal.

**Stack:** Astro 7 · React · Tailwind CSS v4 · Cloudflare Workers · D1 + Drizzle ORM · Cron Triggers · Resend · USPS Addresses API

## Getting started

This project uses [Bun](https://bun.sh) as the package manager.

```bash
bun install
cp .dev.vars.example .dev.vars      # fill in keys as you get them
bun run db:migrate:local            # create tables in the local D1 database
bun run db:seed:local               # add placeholder products
bun run dev                         # http://localhost:4321
```

Use `bun run`, not `bun --bun run`. The `--bun` flag runs Astro on Bun's own runtime, and the Cloudflare dev server does not start under it. The site itself runs on Cloudflare's runtime in both dev and production, so Bun speeds up installs and scripts, not the site.

Local development runs entirely on your machine (Cloudflare's runtime and a local D1 database). No Cloudflare account is needed until deploy.

## Scripts

| Command | What it does |
| --- | --- |
| `bun run dev` | Dev server |
| `bun run build` | Production build into `dist/` |
| `bun run preview` | Build, then run the built Worker locally with Wrangler |
| `bun run db:generate` | Create a new migration after editing `db/schema.ts` |
| `bun run db:migrate:local` / `:remote` | Apply migrations to local / production D1 |
| `bun run db:seed:local` | Load `db/seed.sql` into the local database |
| `bun run cf-typegen` | Regenerate Cloudflare binding types after editing `wrangler.jsonc` |
| `bun run deploy` | Build and deploy to Cloudflare |

## Structure

```
db/
  schema.ts            products, orders, order_items
  migrations/          SQL generated by drizzle-kit
  seed.sql             placeholder products (replace with real data)
src/
  worker.ts            Worker entry: Astro requests + cron for payment reminders
  lib/
    db.ts              D1 + Drizzle client
    store-config.ts    shipping rates, bottle limit, reminder timings, order numbers
    reminders.ts       finds unpaid orders due a reminder (emails added in Phase 4)
  styles/global.css    design tokens from the brief
  layouts/Base.astro
  components/          ProductCard, checkout/, admin/
  pages/
    index.astro        storefront
    order.astro        checkout (Phase 3)
    admin/             admin portal (Phase 5, protected by Cloudflare Access)
    api/               server endpoints (address check, orders)
  emails/              React Email templates (Phase 4)
```

## Emails

Templates are in `src/emails/templates.tsx` and are sent through Resend from `src/lib/notifications.ts`:

- Order received (customer) and new order alert (client), when an order is placed
- Payment reminders, from the cron in `src/lib/reminders.ts`
- Confirmed, shipped and cancelled, sent by the admin portal through `sendStatusEmail`

Without `RESEND_API_KEY` in `.dev.vars`, nothing is sent: each email is logged in the terminal instead. Preview every email at `http://localhost:4321/dev/emails` (local only). The wording is placeholder until the client sends the current site's emails.

To test reminders locally, run `bun run preview`, then trigger the cron:

```bash
curl -X POST "http://localhost:8787/cdn-cgi/local/explorer/api/local/scheduled?worker=precise-formulations" -H "content-type: application/json" -d '{"cron":"*/15 * * * *"}'
```

## Admin portal

`/admin` lists orders with status tabs and search. Each order page has the next step: **Mark as paid**, **Mark as shipped** (with tracking number), **Cancel** (unpaid only) and tracking corrections. Each action emails the customer, and an action only applies if the order is still in the expected status, so double clicks are safe.

Locally the admin opens without sign-in. In production every `/admin` and `/api/admin` request must carry a valid Cloudflare Access token (checked in `src/middleware.ts`); until Access is set up, the admin returns 403.

Setting up Access at launch:

1. In Cloudflare Zero Trust, create a self-hosted Access application for `preciseformulations.cc/admin*` and `preciseformulations.cc/api/admin*`, with a policy allowing the client's email (one-time PIN login is fine).
2. Copy the team domain (e.g. `precise.cloudflareaccess.com`) and the application's **Audience (AUD) tag** into `ACCESS_TEAM_DOMAIN` and `ACCESS_AUD` in `wrangler.jsonc`.
3. Deploy, then open `/admin` in a private window to check that sign-in is required.

## Waiting on the client

Values in `src/lib/store-config.ts` and `db/seed.sql` are placeholders until these are confirmed:

- Bottle limit: 4 per order, or 4 of each product
- Exact reminder timings (first one is 30 minutes)
- Shipping carrier for tracking links (assumed USPS)
- Wording of the current site's emails
- The client's time zone for admin dates (`ADMIN_TIMEZONE`, assumed New York)
- Final product names, prices, ingredients, strength, size and images

## Before the first deploy

1. Get added as a member of the client's Cloudflare account (Workers Paid plan).
2. `bunx wrangler d1 create precise-formulations-db` and paste the `database_id` into `wrangler.jsonc`.
3. `bun run db:migrate:remote`
4. Add secrets: `bunx wrangler secret put RESEND_API_KEY` (and the USPS and Turnstile keys).
5. Set up Cloudflare Access on `/admin*`.
6. `bun run deploy`
